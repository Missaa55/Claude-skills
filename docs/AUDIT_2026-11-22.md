## Issues found and fixes

1. **Installer state path traversal:** an untrusted state file could contain a relative or absolute path outside the target. The installer now rejects unsafe state paths before any read/write/delete. Added tests for parent traversal and absolute paths.
2. **Standalone Cleaner was missing:** fixed earlier by packaging the actual scanner into the chosen builder's quality-cleaner skill.
3. **Uninstall left metadata:** fixed earlier by removing the state file after the final module is uninstalled.
4. **Fabric toolchain failures:** fixed Loom compatibility, plugin identifier and Yarn/Mojang mapping mismatch based on actual failed CI builds.

## Explicit limitations / not verified

- No Claude/Codex CLI end-to-end run with authenticated AI generated a web, app or Minecraft project from a blank workspace.
- WebBuilder has no real browser screenshot, visual regression or deployed website test.
- AppBuilder has no real end-to-end application/database/auth integration test.
- Fabric was built and JAR-inspected, but not launched inside Minecraft for an in-game block/recipe test.
- The runtime executes unsandboxed third-party CLI/build processes; do not use on untrusted workspaces.
- The installer is not transactional on unexpected mid-install disk failures.
- The Quality Cleaner uses string heuristics, not semantic AI-slop detection or reference-aware unused-file analysis.
- No independent one-click installers or signed releases have been published.

**Conclusion:** Installation, removal, isolation and synthetic cleaner behavior have real cross-platform evidence; Minecraft compilation has real Gradle evidence. Claims of full autonomous builder functionality would be premature.
